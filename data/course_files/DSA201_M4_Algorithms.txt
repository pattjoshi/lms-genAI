DSA201 - Algorithms
===================

This module covers two families of algorithms that appear everywhere: sorting, and dynamic programming for problems with overlapping subproblems.

Sorting Algorithms
------------------

Prerequisites: Arrays, Big-O Notation, Recursion.

Simple sorts such as bubble sort, selection sort and insertion sort use nested loops and take O(n squared) time. Insertion sort is still useful: it is fast on small or nearly sorted arrays.

Merge sort is a divide-and-conquer algorithm: split the array in half, sort each half recursively, and merge the two sorted halves. It always runs in O(n log n) and is stable, meaning equal elements keep their original order, but it needs O(n) extra memory.

Quick sort picks a pivot, partitions the array into elements smaller and larger than the pivot, and sorts each part recursively. It averages O(n log n) and sorts in place, but a consistently bad pivot gives the worst case of O(n squared); choosing the pivot randomly makes that very unlikely.

Heap sort uses a heap and guarantees O(n log n) with O(1) extra memory but is not stable. No comparison-based sort can do better than O(n log n) in the worst case. Python's built-in sort uses Timsort, a hybrid of merge sort and insertion sort that is stable and very fast on real-world data.

Dynamic Programming
-------------------

Prerequisites: Recursion.

Dynamic programming (DP) solves problems by breaking them into overlapping subproblems and solving each subproblem only once. It applies when a problem has two properties: optimal substructure, meaning the best solution is built from best solutions to subproblems, and overlapping subproblems, meaning the same subproblems are needed again and again.

There are two styles. Top-down DP, or memoization, writes the natural recursive solution and caches each result the first time it is computed. Bottom-up DP, or tabulation, fills a table iteratively starting from the smallest subproblems, which avoids recursion depth limits.

Fibonacci shows the effect: naive recursion takes exponential time, while DP computes each of the n values once, giving O(n) time.

Classic DP problems include the 0/1 knapsack problem, the longest common subsequence of two strings, coin change and edit distance. A good method is to first define the state, for example dp[i] as the best answer for the first i items, then write the recurrence that relates a state to smaller states, then identify the base cases.
