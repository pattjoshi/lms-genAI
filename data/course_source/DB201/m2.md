# SQL Basics

SQL (Structured Query Language) is how you ask a relational database questions. This module covers reading data from a single table.

## SELECT Queries

Prerequisites: Tables and Keys.

The SELECT statement reads data. The simplest form is `SELECT full_name, email FROM users;` which returns those two columns for every row. `SELECT *` returns all columns, which is handy for exploring but should be avoided in application code because it fetches unnecessary data and breaks when columns change.

Column aliases rename output columns with AS, for example `SELECT price_inr AS price FROM courses;`. Expressions can compute new values, such as `price_inr * 0.9 AS discounted_price`. DISTINCT removes duplicate rows, for example `SELECT DISTINCT city FROM users;`.

SQL is declarative: you describe what result you want, not how to get it. The database's query planner decides the actual steps, such as which index to use.

Although we write SELECT first, the database logically evaluates clauses in this order: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT. This explains why a column alias defined in SELECT cannot be used in WHERE: WHERE runs before SELECT.

## Filtering and Sorting

Prerequisites: SELECT Queries.

The WHERE clause keeps only rows that satisfy a condition, for example `WHERE role = 'student'`. Conditions use comparison operators (=, <>, <, >, <=, >=) and combine with AND, OR and NOT; use parentheses to make the precedence clear.

Useful operators: IN matches any value in a list, as in `city IN ('Pune', 'Delhi')`. BETWEEN matches an inclusive range. LIKE matches patterns, where % stands for any sequence of characters, so `email LIKE '%@student.lmsdemo.in'` finds student emails.

NULL means "unknown", so `column = NULL` is never true. Always use `IS NULL` or `IS NOT NULL`.

ORDER BY sorts the result, ascending by default or descending with DESC, for example `ORDER BY score_pct DESC`. You can sort by several columns. LIMIT restricts the number of rows returned, as in "top 10 scores", and OFFSET skips rows for paging. Without ORDER BY, the order of rows is not guaranteed, even if it looks stable.

## Aggregation and GROUP BY

Prerequisites: Filtering and Sorting.

Aggregate functions summarise many rows into one value: COUNT, SUM, AVG, MIN and MAX. For example, `SELECT AVG(score_pct) FROM quiz_attempts;` returns the overall average score. COUNT(*) counts rows, while COUNT(column) counts only non-NULL values.

GROUP BY splits rows into groups and applies the aggregate to each group: `SELECT course_id, COUNT(*) FROM enrollments GROUP BY course_id;` counts enrollments per course. Every selected column must either be in the GROUP BY or be inside an aggregate function.

HAVING filters groups after aggregation, while WHERE filters individual rows before grouping. To find courses with more than 50 enrollments, write `GROUP BY course_id HAVING COUNT(*) > 50`. Putting an aggregate condition in WHERE is a common error.

Aggregation is how dashboards are built: revenue per month, average score per topic, and drop-out rate per course are all GROUP BY queries.
